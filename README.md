# Student Management System API

**EWB internship assignment — Python Backend Development**

This project manages student records through a Python API. It uses **FastAPI** to receive requests and **SQLite** to save data. A local **Ollama** question-answering feature is included as an optional extension; the main CRUD application does not need Ollama.

## What it does

- Create a student record.
- List students or filter by name, course, or birth year.
- View one student by ID.
- Replace all student details with `PUT`.
- Update selected fields with `PATCH`.
- Delete a student.
- Validate inputs and return useful errors for missing records.
- Save records in a SQLite file so they survive application restarts.
- Optional: ask natural-language questions about records using a local Ollama model.

## Technology

- Python 3.10 or newer
- FastAPI — defines the HTTP API endpoints
- Uvicorn — runs the development web server
- SQLite — stores student data in a local database file
- Pydantic — validates incoming data
- Ollama (optional) — runs a local language model

## 2. Run the API

From the project root, run:

```bash
python -m uvicorn main:app --reload
```

Open these addresses in your browser:

- API welcome: http://127.0.0.1:8000/
- Interactive API documentation: http://127.0.0.1:8000/docs
- Health check: http://127.0.0.1:8000/health

The database is created automatically at `data/students.db` the first time the app starts. To use another path, set `STUDENT_DB_PATH` before starting the server.

### Windows PowerShell — custom database path (optional)

```powershell
$env:STUDENT_DB_PATH = "data/students.db"
python -m uvicorn main:app --reload
```

## 3. API endpoint guide

| Method | Endpoint | Purpose |
|---|---|---|
| `POST` | `/students` | Add a new student |
| `GET` | `/students` | List students; optional filters below |
| `GET` | `/students/{student_id}` | Find one student |
| `PUT` | `/students/{student_id}` | Replace all editable fields |
| `PATCH` | `/students/{student_id}` | Update only fields supplied |
| `DELETE` | `/students/{student_id}` | Delete a student |
| `POST` | `/students/ask` | Optional Ollama question-answering |

List filters:

- `?name=asha` — partial, case-insensitive name search
- `?course=ECE` — case-insensitive exact course match
- `?born_after_year=2005` — students born after December 31, 2005
- `?limit=50&offset=0` — basic pagination

Every student must have a name, a date of birth in `YYYY-MM-DD` format, and at least one contact method (email or phone). Student IDs are generated by the database. The email check is a simple format check and does not prove that an address exists.

## 4. Try a request

In the built-in Swagger page at `/docs`, expand `POST /students`, click **Try it out**, and send this example:

```json
{
  "name": "Asha Kumar",
  "date_of_birth": "2005-04-12",
  "email": "asha@example.com",
  "phone": "9000000001",
  "course": "ECE",
  "address": "Hassan, Karnataka",
  "enrollment_date": "2024-08-01"
}
```

You should receive HTTP `201 Created` and a response containing a generated `id` and timestamps. Use that ID with the other endpoints. More examples are in `sample_requests.http`.

## 5. Optional AI extension with Ollama

The AI endpoint is **optional**. Complete and test the CRUD API first.

1. Install Ollama from its official site and ensure the local Ollama service is running.
2. Download the example model:

   ```bash
   ollama pull llama3.2:1b
   ```

3. Start this FastAPI application in another terminal.
4. Send a `POST` request to `/students/ask`:

   ```json
   {
     "question": "How many students are there?"
   }
   ```

Other example: `{"question":"List students born after 2005"}`.

The backend runs safe, fixed, parameterized database queries in Python and passes the returned records/count to Ollama as context. **The language model does not get database credentials and does not execute SQL.** If Ollama is not installed or running, `/students/ask` returns a clear `503` error; the main CRUD endpoints continue to work.

Optional environment settings:

```text
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=llama3.2:1b
```

## How to explain it in a project review

> “This is a student record management backend built with Python and FastAPI. The API receives HTTP requests and validates the input using Pydantic. The route functions run parameterized SQL statements against an SQLite database. The CRUD endpoints create, retrieve, update and delete student records. SQLite stores the records between restarts. I also added an optional Ollama endpoint: the backend retrieves matching data first and supplies it to the model as context, so the model does not execute SQL directly.”

## Notes / limitations

- This is an educational local-development project, not a production college information system.
- The API currently has no login/authentication or role-based access control. Do not expose it publicly with real student data.
- The local AI feature is only as accurate as the retrieved database context and the local model response. Verify outputs before relying on them.
- The optional AI question parser intentionally supports a small set of simple question patterns. It is not a general-purpose natural-language-to-SQL engine.
